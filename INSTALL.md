# Probe Fast — упрощённая редакция 8.3-fast.6

Основа: Probe 8.3; схема 8.0. Оригинальный Probe не изменён. Структура результатов возвращена к обычному Probe:

```text
<change>/reviews/<run-id>/
  observations.md
  report.md
  review-details.md
  _meta/
    inputs.json
    freshness.json
    report.json
    publication.json
```

Один report.json, без parts, manifest, реестра доказательств и событий времени. Сохранены выбор области ревью, пакетное чтение, правила доказательности и обоснование повторных тестов. Расширения схемы: необязательный in_scope для наблюдений вне выбранных сабтасков и reference_map/ref_id для повторяющихся ссылок покрытия. Оно не создаёт дополнительных файлов.

## Установка и обновление

Скопируйте agents/openspec-spec-probe-fast.md и файлы из agents/openspec-spec-probe-fast/ в соответствующие места .gigacode/agents/. Обновите вместе инструкцию, report.schema.json, scripts/runner.py и scripts/report.py. Не заменяйте весь каталог agents и не затрагивайте обычный Probe.

Для чистого обновления перенесите прежний установленный каталог openspec-spec-probe-fast/ целиком в резервную папку вне .gigacode/agents, затем установите свежий каталог из этого пакета. Это исключит оставшиеся инструкции, скрипты и кэш старой версии. Соседний файл openspec-spec-probe-fast.md тоже замените. Остальных агентов не затрагивайте. Предыдущие каталоги reviews сохраняйте: новая версия их не читает и не преобразует.

В установленном служебном каталоге достаточно трёх файлов:

```text
report.schema.json
scripts/runner.py
scripts/report.py
```

Начните новую сессию, чтобы старые инструкции о parts и тайминге не остались в контексте. Если ранее добавляли проектную заметку о fast.3, обновите её: новый прогон использует один report.json. tests/ не нужно устанавливать в каталог агентов.

## Выбор области основным агентом

До вызова Probe определите область из явного запроса пользователя. Не спрашивайте повторно при однозначном запросе. Если пользователь просит только «запусти Probe», уточните: «Проверить весь change или выполненные/конкретные сабтаски из subtasks.md?» Наличие subtasks.md само по себе не определяет режим.

Передайте субагенту один из вариантов:
- `review_mode: full_change` — полный change;
- `review_mode: completed_subtasks`, `subtasks_path: <путь>` — выполненные сабтаски; Probe установит список после freeze;
- `review_mode: selected_subtasks`, `subtasks_path: <путь>`, `subtask_ids: [<ID>, <ID>]` — конкретные сабтаски.

Это параметры задания в тексте вызова, не новые флаги runner.py. Передавайте только режим, ID, пути, ревизии и ограничения; не передавайте содержание требований или старые отчёты. Если Probe возвращает вопрос о неоднозначной выборке, передайте его пользователю и верните ответ субагенту. Не выбирайте за пользователя.

Примеры пользовательских запросов:

> Вызови openspec-spec-probe-fast для полного change <путь-change>.

> Вызови openspec-spec-probe-fast для выполненных сабтасков из <путь-change>/subtasks.md.

> Вызови openspec-spec-probe-fast для сабтасков <ID-1> и <ID-2> из <путь-change>/subtasks.md.


После прогона для анализа достаточно передать report.md, review-details.md и при необходимости _meta/report.json, observations.md и журнал вызова. Ускорение не гарантируется: эта редакция устраняет накладные расходы формата.

## Проверки в fast.5

Lint, типы, тесты и необходимая сборка выполняются единым финальным этапом после сопоставления и до публикации. Один достаточный запуск на вид проверки; повтор — только с новым основанием. Ранний целевой запуск разрешён, если нужен для анализа, и без изменения входов не дублируется в конце. Обязательные правила проекта сохраняются; full_change не означает автоматический запуск всех проверок проекта. Каталог _meta остаётся из четырёх штатных файлов.

## Компактные данные fast.6

Обновите вместе файл агента, report.schema.json и scripts/report.py. Повторяющиеся ссылки coverage хранятся один раз в reference_map того же report.json. Генератор раскрывает их в приложении. Старый формат с ref поддерживается. Основной отчёт, поля находок и листинги не изменены; пояснения успешных проверок пишутся кратко без потери доказательств. Дополнительных файлов нет.
