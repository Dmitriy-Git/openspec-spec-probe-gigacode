# Парный пилот OpenSpec Verify и Probe 7.0

Выберите два завершённых change: один типичный, второй с ручными правками после apply или несколькими сервисами. Запишите путь change, SHA базы и HEAD каждого сервиса, ревизию основной спеки до sync и версии доступных экспортов требований. Используйте одинаковые снимки рабочих деревьев, включая новые файлы, одинаковую модель и доступ к тестам. Откройте отдельную чистую сессию для каждой команды. Не передавайте второму участнику результаты первого. Если store общий, исключите reviews/ из чтения в обоих проходах.

### Команды в GigaCode

1. В сессии с установленным OpenSpec Verify выполните `/opsx:verify <change-id>`. В контексте сессии заранее укажите пути store и сервисов, базы и источники. Попросите проверить текущие рабочие правки и исключить reviews/. Сохраните ответ отдельно.
2. В новой сессии отправьте: «Вызови openspec-spec-probe для <путь-change>. Сервисы и базы: <имя, путь, SHA>. Основная спека до sync: <ревизия>. Требования: <экспорты>. Проверь текущее рабочее дерево. Передай субагенту пути и ревизии, исключи содержимое change и предыдущих отчётов из стартового контекста». Сохраните report.md и observations.md.

### Карточка результата

| Change | Факт и место | Verify / Probe / оба | Оценка владельца | Принятое действие |
|---|---|---|---|---|
| | | | Подтверждено / ложная находка / открыто | Правка спеки / дефект кода / уточнение / без действия |

Сведите дубли по поведению и условию. Для каждого инструмента посчитайте подтверждённые уникальные находки и ложные срабатывания, отдельно укажите открытые вопросы, длительность и объём чтения, если он доступен. Отметьте непроверенные сценарии. По истории действий проверьте, что модель не получила текст change до freeze. Если история недоступна, оставьте порядок чтения неподтверждённым.

При анализе отчёта 7.0 различайте полный проход, частичный (partial_review) и невозможный (unable_to_review). Изменение зафиксированного входа делает результат непригодным для сравнения. Синтетический пример и тесты скриптов не входят в измерения качества модели.
