# Probe Fast — отдельная экспериментальная копия

Основа: Probe 8.3; редакция 8.3-fast.3; схема 8.0.

Скопируйте файл `agents/openspec-spec-probe-fast.md` и каталог `agents/openspec-spec-probe-fast/` в `.gigacode/agents/` проекта. Объедините каталоги, не заменяйте `.gigacode/agents/` целиком. Существующий Probe и его служебные файлы остаются на месте. Не удаляйте других агентов. Проверьте `/agents manage`; при необходимости откройте новую сессию.

Запуск в чистой сессии:

> Вызови openspec-spec-probe-fast для полного change <путь-change>; режим full_change. Сервисы и базы: <имя, путь, SHA>. Передай только пути, ревизии и ограничения; требования и обсуждения открывай после freeze. Исключи предыдущие отчёты из контекста и поиска. Проверь текущую реализацию, включая незакоммиченные изменения.

Результаты: новый каталог `<change>/reviews/<run-id>/`, основной `report.md`, приложение `review-details.md` и `observations.md`. Используется Python 3 без внешних зависимостей. Модель наследуется, как у оригинала.

Изменения: пакетные чтения внутри фазы, повторное использование проверенных доказательств в текущем прогоне, группировка связанных тестов, заполнение coverage по мере анализа и исключение промежуточных текстовых отчётов. Полнота проверки, freeze, правила находок и вердиктов сохранены. В fast.3 схема поддерживает реестр доказательств, report.py собирает записи и генерирует ссылки, workflow.py измеряет команды, runner.py фиксирует хеш нового скрипта.

Ускорение и сохранение качества пока не подтверждены реальными прогонами. Протокол сравнения — `evaluation.md`. Исходные файлы этой копии зафиксированы в `source-manifest.json`.

## Выбор области основным агентом

До вызова Probe определите область из явного запроса пользователя. Не спрашивайте повторно при однозначном запросе. Если пользователь просит только «запусти Probe», уточните: «Проверить весь change или выполненные/конкретные сабтаски из subtasks.md?» Наличие subtasks.md само по себе не определяет режим.

Передайте субагенту один из вариантов:
- `review_mode: full_change` — полный change;
- `review_mode: completed_subtasks`, `subtasks_path: <путь>` — выполненные сабтаски; Probe установит список после freeze;
- `review_mode: selected_subtasks`, `subtasks_path: <путь>`, `subtask_ids: [<ID>, <ID>]` — конкретные сабтаски.

Это параметры задания в тексте вызова, не новые флаги runner.py. Передавайте только режим, ID, пути, ревизии и ограничения; не передавайте содержание требований или старые отчёты. Если Probe возвращает вопрос о неоднозначной выборке, передайте его пользователю и верните ответ субагенту. Не выбирайте за пользователя.

Примеры пользовательских запросов:

> Вызови openspec-spec-probe-fast для полного change <путь-change>.

> Вызови openspec-spec-probe-fast для выполненных сабтасков из <путь-change>/subtasks.md.

> Вызови openspec-spec-probe-fast для сабтасков <ID-1> и <ID-2> из <путь-change>/subtasks.md.

Для обновления fast.1 до fast.2 замените только agents/openspec-spec-probe-fast.md в установленном каталоге и используйте эти инструкции вызова. Это правило относилось к fast.2; для fast.3 обновляйте весь комплект по разделу ниже. Правила основного агента не устанавливаются автоматически: передайте ему этот раздел или включите соответствующие указания в запрос запуска.

## Обновление до fast.3

Замените файл agents/openspec-spec-probe-fast.md и весь комплект служебных файлов agents/openspec-spec-probe-fast/ соответствующими файлами этой копии, включая WORKFLOW.md, workflow.py, runner.py, report.py и схему. Для fast.3 обновления только Markdown агента недостаточно. Старый Probe не затрагивайте. Откройте новую сессию. Реестр доказательств, сборка из записей и измерения описаны в WORKFLOW.md. Не копируйте tests/ в каталог агентов.
