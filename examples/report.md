### F-01 · 🔴 Высокая · Истёкший OTP принимается при подтверждении

Тип: дефект реализации

**Почему это важно**

Код можно использовать после истечения срока действия, что нарушает требование ограничения времени подтверждения.

#### Решение

**Сохранить требование**

**Основание решения**

Сценарий однозначно требует отклонять истёкший OTP.

#### Как описано в исходном change

📄 `specs/auth/spec.md`

Место: сценарий «Истёкший код»

Сценарий «Истёкший код»: после expires_at подтверждение должно отклоняться. Требование приведено для иллюстрации.

#### Как реализовано в коде

📄 `auth/verify.py`

Место: 42–47 (синтетический пример)

```python
# Синтетический пример, не код проекта.
def verify_otp(record, supplied_code):
    if record.code != supplied_code:
        return False
    return True
```

Синтетический пример: обработчик сравнивает значение OTP, но не проверяет expires_at. Реальный код не проверялся.
